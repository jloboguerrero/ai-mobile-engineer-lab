# i18n — English + Spanish from day one

- i18next + react-i18next + expo-localization; the app's own instance in `core/i18n.ts`.
- One catalog per area: `src/<area>/locales/en.ts` (`export const en = {…} as const`) and
  `es.ts` typed against it (`export const es: Catalog<typeof en> = {…}`), registered in
  `src/translations.ts` (`en: { ui, timeOff, … }, es: { … }`). Only the root layout imports it.
- Keys are typed: a misspelt key fails `tsc`; a missing Spanish key fails `tsc`.
- **Both languages in the same edit.** Every screen uses keys — worker tabs included.
- Components: `useTranslation('<namespace>')`; plain modules: `i18n.t` from `@/core/i18n`.
- Language: the first of the phone's languages with a catalog, else English (read at launch).
  A manual selector in Me is an open product question.
- Server messages are English: map known ones to keys; unknown ones shown as-is.
- Enums: value → key (`t(\`status.${status}\`)`); never send the label to the API.
- Never build a sentence from pieces. Counts: `{ count }` with `_one` / `_other` keys.

## Dates & numbers

- A date written with words: `format(d, pattern, { locale: dateLocale() })`.
- **Calendar days** (time off days, dob, effectiveDate, pay date): `calendarDay(value)` /
  `usDate(value)` from `core/format/dates.ts`; no timezone conversion.
- **Instants** (created, signed, uploaded): shown in the phone's zone.
- Money: `core/format/money.ts` (USD).
- Wire formats (`MM/dd/yyyy`) only inside `data/mappers.ts`.
- Rules that depend on today take an injectable `now`.
